# 9. Training SFNN-1536 (NNUEwoSQPT1536)

<a href="../../ja/tutorial/9-sfnn-1536.md"><img alt="日本語で読む" src="https://img.shields.io/badge/Lang-日本語-DC2626?style=flat-square"></a>

Train an evaluation function that runs on YaneuraOu's `YANEURAOU_ENGINE_NNUE_SFNNwoP1536` build (a.k.a. NNUEwoSQPT1536). SFNN-1536 belongs to the **LayerStacks family** and differs from ordinary NNUE in:

- **9 independent MLPs (LayerStacks=9)**; one is selected per position by `(friend_king_rank/3, enemy_king_rank/3)` (3×3 = 9 buckets).
- Input feature is **HalfKA_hm2** (= HalfKA + half-mirror + enemy king collapsed onto the friend plane).
- The L1 output is split through both **SqrClippedReLU and ClippedReLU** and concatenated (Stockfish-style pairwise output).
- **PSQT shortcut**: the L1 has one extra neuron that bypasses L2/L3 and is added straight into the final scalar.

## 9.1 Command

Minimal:

```bash
./target/release/examples/bulletou \
    --eval-type SFNN_HALFKA2HM \
    --arch 1536x2-15-32 \
    --layerstack king3-by-king3 \
    --teacher teachers/
```

This matches `architectures/sfnnwop-1536.h` byte-for-byte. With `--output` omitted, checkpoints land under `checkpoints/SFNN_HALFKA2HM-1536x2-15-32-king3-by-king3/`.

## 9.2 Choosing v1 vs v2

Two `--eval-type` candidates:

| Flag | Input feature | Input dim | Engine-loadable | When to pick |
|---|---|---|---|---|
| **`SFNN_HALFKA2HM`** ★ default choice | `HalfKA_hm2` (enemy-king collapse) | 73,305 | yes (`SFNNwoP1536` build) | This is what you train if you want to ship it to YaneuraOu |
| `SFNN_HALFKA1HM` | `HalfKA_hm1` (no collapse) | 76,950 | no | Ablation only — comparing strength when both kings are kept on separate planes |

The only difference is the input-feature module. Network topology, quantisation, and the LayerStacks plumbing are identical.

## 9.3 The `--layerstack` flag

`--layerstack` selects how the 9 sub-networks are dispatched:

| Flag | Bucket selection | Engine-loadable | Notes |
|---|---|---|---|
| **`king3-by-king3`** (default) | Friend-king-rank 3-way × enemy-king-rank 3-way = 9 | yes | Matches YaneuraOu's `stack_index_for_nnue` exactly |
| `ply9` | 9 buckets by move count (`SHOGI_PLY_BUCKET9_DEFAULT_BOUNDS`) | dim-compatible only (\*) | Ablation only |

(\*) "Dim-compatible" means the engine can structurally load the `nn.bin`, but the per-position bucket the engine picks does not match the bucket the network was trained on, so the resulting strength is broken. Don't ship a `ply9` model.

## 9.4 What `--arch 1536x2-15-32` builds

The network constructed for `--arch 1536x2-15-32` (per `sfnnwop-1536.h`):

```
Feature Transformer (l0):  73,305 → 1,536  (per perspective)
[CReLU + pairwise-mul + (127/128)] × 2 perspectives → concat → 1,536

For each of 9 buckets (selected by --layerstack):
  L1:   1,536 → 16  (= 15 hidden + 1 PSQT shortcut neuron)
  ─ split: l1_main (15 dim) / l1_skip (1 dim, PSQT shortcut)
  l1_sqr = l1_main² × (127/128)
  L2_input = concat(l1_sqr, l1_main)            // 30 dim, [SqrCReLU; CReLU]
  CReLU → L2:  30 → 32
  CReLU → L3:  32 → 1

Final scalar = L3_out + l1_skip                  // PSQT bypass
```

`--arch` is mapped internally to `(ft_size, l1_hidden, l2_size) = (1536, 15, 32)`. The PSQT shortcut neuron (`l1_hidden + 1`) is added automatically.

## 9.5 Important caveats

### YaneuraOu-loadable `nn.bin` is **not yet implemented**

The current bulletou writes only `state.bin` (the optimiser state, used for resume) for the SFNN family. The `nn.bin` layout that YaneuraOu's engine can load via `EvalDir` is in a follow-up commit (Phase 4 of the SFNN-1536 work).

Right now:
- ✓ `--eval-type SFNN_HALFKA2HM` actually trains end-to-end.
- ✓ `state.bin` is written at every save; resume works.
- ✓ `learn.log` records the loss curve in the same 9-column CSV as every other eval-type.
- ✗ `nn.bin` is either empty or non-loadable. **Do not point YaneuraOu's `EvalDir` at these saves yet.**

If you need to ship a trained SFNN to YaneuraOu before Phase 4 lands, use `examples/shogi_layerstack.rs` (it produces an rshogi-compat `quantised.bin`, with its own usage instructions in that file's header doc-comment).

### `--arch` is effectively `1536x2-15-32` only

YaneuraOu's SFNN build ships exactly one preset (`sfnnwop-1536.h`). Other `--arch` values (`256x2-32-32` etc.) train, but the resulting weights cannot be loaded by YaneuraOu **even after Phase 4** — they're for ablation only.

### LayerStacks=9 is fixed

Both `king3-by-king3` and `ply9` produce **9 stacks** because YaneuraOu's `nn.bin` reader expects exactly 9. Other bucket counts (e.g. `progress8` from `examples/shogi_layerstack.rs`) are not reachable through this CLI.
