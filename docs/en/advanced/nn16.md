# Export nn16.bin

`export-nn16` exports FP32 SFNN `state.bin` with int16 L1/L2/L3 weights and int32 biases.
FT remains int16. Ordinary training, QAT, nn.bin and live qvalid are unchanged.
This experimental format needs corresponding engine reader and inference changes (not included).
An int8 nn.bin cannot restore the original FP32 precision: use the matching state.bin.

```powershell
$checkpoint = "D:\BulletOu-snapshots\your-run\0023"
.\target\release\examples\bulletou.exe export-nn16 `
  --arch SFNN_halfka2_1024_8_64_progress8 `
  --state-bin "$checkpoint\state.bin" `
  --weight-scale 4096 `
  --output "$checkpoint\nn16.bin"
```

`--settings-file` defaults to `bulletou-settings.json` beside state.bin; missing settings are an error.
Use settings and count.bin from save time, not modified training settings. FT/shared coefficients recorded
in state take precedence. Folding uses the existing FT/residual/shared/axis implementation; no rebasing,
optimizer allocation or GPU is involved. The progress classifier is saved separately as progress.bin.
Existing output files are not overwritten; an identical progress sidecar is preserved, a conflicting one errors.
Output defaults to nn16.bin in the working directory. Complete files are published via a same-volume hard link
(NTFS or another supporting filesystem required).

`QA=127`, `QB=4096` by default. `--weight-scale` accepts powers of two in 64..16384.
FC weights use round(QB*w), biases round(QA*QB*b), ties away from zero. Out-of-range FC values are errors,
not silent saturation. FT retains its original int16 clamp. At 4096 the grid is 1/4096 (64 times finer than
int8/64), weights span [-8, 7.999755859375], and biases use scale 520192.

## Engine binary contract

All integers are little-endian. `pad32` rounds up to a multiple of 32 elements.

```text
u32 version = 0x7AF32F17 (old nn.bin: 0x7AF32F16)
u32 model_hash = 0x3C203B32
u32 description byte length
UTF-8 description, no NUL
u32 QB                              # new field
u32 FT_hash = 0x5F134AB8
signed-LEB128 block: int16 FT bias[FT]
signed-LEB128 block: int16 FT weights[input_features][FT]
repeat for each bucket:
    u32 network_hash = 0x6333718A
    int32 L1 bias[H1 + skip]
    int16 L1 weights[H1 + skip][pad32(FT)]
    int32 L2 bias[H2]
    int16 L2 weights[H2][pad32(2*H1)]
    int32 L3 bias[1]
    int16 L3 weights[pad32(H2)]
```

LEB128 blocks retain the 17-byte `COMPRESSED_LEB128` marker, u32 payload size and signed-LEB128 payload.
FC weights are output-major, padding is zero, with no SIMD scrambling on disk.
The description appends `;FCWeightBits=16;QB=4096;H1=8;Skip=0;H2=64` to the existing SFNN description.
The reader must check version and QB even though the existing hashes are retained.

FT and 8-bit activations are unchanged. With `s=log2(QB)` and affine sum `z`:

```text
CReLU(z)    = clamp(z >> s, 0, 127)
SqrCReLU(z) = min((z*z) >> (2*s+7), 127)
```

The square includes negative z. L2 input is `[SqrCReLU; CReLU]`; add the L1 skip sum to L3 if present.
At QB=4096 shifts are 12 and 31. Use safe accumulation and squaring: the CPU reference uses int64 and int128.
int16 weights do not guarantee int32 sums are safe. Early saturation checks can also avoid square overflow.

`network_output ≈ raw16/(127*QB) = raw16/520192`. Old raw units are `raw16*64/QB = raw16/64`.
For the scale of old FV_SCALE=24 use `raw16/1536`, **not raw16/24**, or normalize to old raw units first.
Teacher scales and loss targets do not change. QAT optimized for int8/64 may not benefit; measure it.

## Validation

```powershell
.\target\release\examples\bulletou.exe quantized-test `
  --arch SFNN_halfka2_1024_8_64_progress8 `
  --nn-bin "$checkpoint\nn16.bin" `
  --test-teacher C:\shogi\teacher\test\test20231010_fg2021_dls5_ryfc20_ev8250k825.hcpe `
  --mode cpu-exact `
  --wrm-in-offset 0 --wrm-target-offset 0
```

Only CPU integer validation is currently supported for nn16 (`--mode gpu` errors). QB is read from the file.
Omit `--test-positions` to use all positions. Match training WRM and other loss settings.
Use **train-scale accuracy/loss** to compare with training: decisive-result sign accuracy and loss on
raw16/(127*QB). Engine-scale reporting interprets --fv-scale in old QB=64 units and adjusts the divisor.
CPU activation rounding differs from live GPU proxy qvalid; compare the old and new files using the same CPU path.
