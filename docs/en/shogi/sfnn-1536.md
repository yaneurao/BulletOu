# SFNN-1536 (NNUEwoSQPT1536) Training Reference

<a href="../../ja/shogi/sfnn-1536.md"><img alt="日本語で読む" src="https://img.shields.io/badge/Lang-日本語-DC2626?style=flat-square"></a>

[Back to reference index](../README.md)

`--eval-type SFNN_HALFKA1HM` / `--eval-type SFNN_HALFKA2HM` trains the **LayerStacks-family evaluation function** targeted by YaneuraOu's `YANEURAOU_ENGINE_NNUE_SFNNwoP1536` build (a.k.a. NNUEwoSQPT1536). This page covers the architecture, binary layout, and quantisation in full.

For high-level usage (command examples) see [tutorial §4 Run the training](../tutorial/4-train.md) and [§9 LayerStack](../tutorial/9-layerstack.md).

## Why support it

- YaneuraOu's newest-generation evaluation function (NNUEwoPSQT family) uses **LayerStacks=9** (per-position selection from 9 sub-networks based on king ranks), giving higher accuracy than a single MLP.
- Input feature is **HalfKA_hm2** (= HalfKA + horizontal mirror + enemy king collapsed onto the friend plane).
- Intermediate computation pairs **SqrClippedReLU and ClippedReLU outputs** in concatenation, plus a PSQT shortcut neuron from L1 — adopting modern Stockfish-style patterns.

The difference between `SFNN_HALFKA1HM` (v1) and `SFNN_HALFKA2HM` (v2) is **only the input-feature module**; the network topology, quantisation, and LayerStacks plumbing are identical:

| Flag | Input feature | Input dim | YaneuraOu-loadable | When to pick |
|---|---|---|---|---|
| **`SFNN_HALFKA2HM`** ★ default choice | `HalfKA_hm2` (enemy-king collapse) | 73,305 | yes (`SFNNwoP1536` build) | What you actually ship to YaneuraOu |
| `SFNN_HALFKA1HM` | `HalfKA_hm1` (no collapse) | 76,950 | no | Ablation only — comparing strength with two king planes kept separate |

## Architecture

The network constructed for `--arch 1536x2-15-32` (following YaneuraOu's `architectures/sfnnwop-1536.h`):

```
Input feature (HalfKA_hm2: 73,305 dim × 2 perspectives)
        │
        │  L0 affine (Feature Transformer)
        ▼
   FT output (1,536 dim × 2 perspectives)
        │
        │  CReLU + pairwise-mul × (127/128) → concat → 1,536 dim
        ▼
   ─── For each of 9 buckets (LayerStacks; pick via --layerstack) ───
        │
        │  L1 affine: 1,536 → 16  (= 15 hidden + 1 PSQT shortcut neuron)
        ▼
   ─ split ─
   ├─ l1_main (15 dim)
   │      │
   │      │  l1_sqr = l1_main² × (127/128)          // SqrClippedReLU equivalent
   │      │  L2_input = concat(l1_sqr, l1_main)     // 30 dim, [SqrCReLU; CReLU]
   │      │  CReLU
   │      ▼
   │  L2 affine: 30 → 32 ── CReLU ── L3 affine: 32 → 1
   │                                       │
   │                                       ▼
   └─ l1_skip (1 dim, PSQT shortcut) ───── + ──→ final scalar
```

`--arch 1536x2-15-32` maps internally to `(ft_size, l1_hidden, l2_size) = (1536, 15, 32)`. The PSQT shortcut neuron (`l1_hidden + 1`) is added automatically.

The supported `--arch` is essentially **`1536x2-15-32` only** (the single preset YaneuraOu's SFNN build ships). Other sizes (`256x2-32-32` etc.) will train, but the resulting `nn.bin` is not engine-loadable (= ablation only).

## LayerStacks=9 (bucket selection)

For each position, **exactly one** of the 9 sub-networks is used. Which one is picked depends on the `--layerstack` bucket selection logic. With `--layerstack king3-by-king3` (YaneuraOu-compatible, the only supported value):

| Tier | Friend king rank (`f_rank`) | Enemy king rank (`e_rank`) |
|---|---|---|
| upper (0) | ranks 1-3 | ranks 1-3 |
| middle (1) | ranks 4-6 | ranks 4-6 |
| lower (2) | ranks 7-9 | ranks 7-9 |

→ bucket = `f_part × 3 + e_part` (0 to 8, 9 total). Matches YaneuraOu C++'s `evaluate_nnue.cpp::stack_index_for_nnue` exactly.

See [§9 LayerStack tutorial](../tutorial/9-layerstack.md) for the user-level introduction.

## Output files

During training each save dir contains both `nn.bin` (for the engine) and `state.bin` (for resume), same as the other NNUE eval types:

```
checkpoints/SFNN_HALFKA2HM-1536x2-15-32-king3-by-king3/
├── learn.log                          ← top-level cumulative log
├── 0001/
│   ├── nn.bin                         ← loaded by YaneuraOu SFNNwoP1536 build
│   ├── state.bin                      ← weights + Adam moments for resume
│   └── learn.log                      ← snapshot at this save point
├── 0002/
└── ...
```

## `nn.bin` binary layout

Byte-for-byte compatible with the YaneuraOu source (`source/eval/nnue/evaluate_nnue.cpp` and friends). Implementation lives in `crates/bulletou_lib/src/value/nnue_save_sfnn1536.rs`.

```text
[Header]
  u32 LE: NNUE_VERSION = 0x7AF32F16     ← YaneuraOu kVersion, mismatch = load fails
  u32 LE: kHashValue   = 0x3C203B32     ← SFNNwoPSQT constant, mismatch is warning only
  u32 LE: arch_desc_len
  bytes : "ModelType=SFNNWithoutPsqt;Features=HalfKA_hm2(Friend)[73305->1536x2],Network=SFNN-1536{LayerStack=9}"

[FeatureTransformer]
  u32 LE: FT hash = 0x5F134AB8         ← SFNN-fixed value, warning only
  [LEB128 block: biases]
    17 bytes: "COMPRESSED_LEB128"      ← LEB128 magic
    u32 LE  : payload size
    bytes   : signed-LEB128 encoded i16 × 1536
  [LEB128 block: weights]
    17 bytes: "COMPRESSED_LEB128"
    u32 LE  : payload size
    bytes   : signed-LEB128 encoded i16 × (1536 × 73305)

[× 9 LayerStacks]
  u32 LE: Network hash = 0x6333718A   ← SFNN-fixed value, warning only
  fc_0 biases  : i32 LE × 16          ← scale = QA × QB = 8128
  fc_0 weights : i8 × 16 × pad32(1536) = 24,576 bytes   ← scale = QB = 64, row-major (out, in)
  fc_1 biases  : i32 LE × 32          ← scale = 8128
  fc_1 weights : i8 × 32 × pad32(30)  = 1,024 bytes     ← scale = 64, in-axis zero-padded 30→32
  fc_2 biases  : i32 LE × 1           ← scale = 8128
  fc_2 weights : i8 × 1 × pad32(32)   = 32 bytes        ← scale = 64
```

Hash mismatches are demoted to warnings on the YaneuraOu side (`evaluate_nnue.cpp:178-179` / `:203-209`, with a comment along the lines of "PRs that forgot to update the hash value happen"). Only `NNUE_VERSION` is strictly enforced.

### Quantisation scales

| Section | Type | Scale | Origin |
|---|---|---|---|
| FT biases / weights | i16 | QA = **127** | Stockfish standard (ClippedReLU upper bound ±127) |
| fc_0 / fc_1 / fc_2 biases | i32 | QA × QB = **8128** | (same) |
| fc_0 / fc_1 / fc_2 weights | i8 | QB = **64** | Aligned with YaneuraOu `kWeightScaleBits = 6` (= log2(64)) |

Same values as the upstream bullet-shogi.

### SIMD permutation

YaneuraOu's `AffineTransform*Explicit::get_weight_index_scrambled` is applied **at read time** to map file bytes into the chunk-major in-memory layout. The writer (BulletOu) therefore just emits weights in plain **row-major (out outer, in inner)** order; the engine handles the chunked permutation on load. Padding (in >= in_dim_real) is zero-filled.

For the detailed reasoning see the doc-comments in `crates/bulletou_lib/src/value/nnue_save_sfnn1536.rs`.

## Verifying load in YaneuraOu

After training, point `EvalDir` at the latest save:

```
setoption name EvalDir value C:/shogi/BulletOu/checkpoints/SFNN_HALFKA2HM-1536x2-15-32-king3-by-king3/0005
isready
bench
```

`isready` is expected to emit a warning like this (it is **not** an error):

```
info string Warning: NNUE hash mismatch: expected 1009484594 got 1009484594 ...
```

(YaneuraOu downgrades hash mismatches to warnings and proceeds.)

If `bench` then prints scores, the binary structure is correct.

## Hyperparameter guidance

- Training set should be on the order of hundreds of millions to billions of positions, **shuffled in advance** ([§3.2](../tutorial/3-data.md#pre-shuffle-the-teacher-file)).
- `--lambda` in the 0.5–1.0 range is typical (NNUEwoPSQT is designed to lean on teacher eval).
- `--max-epochs` of 1–3 with `--save-rate 10` and using only the later saves works well in practice.

The general training schedule is shared with [§6 Tune the training](../tutorial/6-tune.md).

## Memory requirements

LayerStacks=9 × `(L1 + L1f + L2 + L3)` weights live on the GPU, so this is heavier than a single-MLP HalfKP. **8 GB+ GPU recommended.** The FT (1536 × 73305 × i16 ≈ 225 MB) also lives on the CPU side.
