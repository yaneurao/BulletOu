# SFNN-1536 (NNUEwoSQPT1536) 学習リファレンス

<a href="../../en/shogi/sfnn-1536.md"><img alt="Read in English" src="https://img.shields.io/badge/Lang-English-DC2626?style=flat-square"></a>

[リファレンス目次へ戻る](../README.md)

`--arch SFNN_halfkahm1_1536_15_32_k3k3` / `--arch SFNN_halfkahm2_1536_15_32_k3k3` は、やねうら王の `YANEURAOU_ENGINE_NNUE_SFNNwoP1536` ビルド (通称 NNUEwoSQPT1536) 向けの **LayerStacks 系評価関数** を学習する。本ページはそのアーキテクチャ・バイナリレイアウト・量子化仕様を網羅する。

実際の使い方の概要 (コマンド例) は [チュートリアル: 学習を走らせる](../tutorial/3-train.md) と [応用編: LayerStack](../advanced/layerstack.md) を参照。

## なぜサポートするか

- やねうら王の最新世代評価関数 (NNUEwoPSQT 系) は **LayerStacks=9** (両玉の段に応じて 9 個のサブネットワークから 1 つを選んで使う) を採用しており、従来の単一 NN より高精度
- 入力特徴量は **HalfKA_hm2** (= HalfKA + 左右対称ミラー + 後手玉を自玉 plane に collapse) を使う
- 中間で **SqrClippedReLU と ClippedReLU の出力ペア** を concat、さらに L0 出力に PSQT shortcut neuron を追加するなど、Stockfish 由来の最新パターンを取り込んでいる

SFNN 系 target の違いは **入力特徴量モジュールだけ**。NN 構造・量子化・LayerStacks の仕組みはすべて共通:

| flag | 入力特徴量 | 入力次元 | やねうら王 load 可 | 用途 |
|---|---|---|---|---|
| **`SFNN_HALFKA2HM`** ★ 通常はこちら | `HalfKA_hm2` (後手玉 collapse あり) | 73,305 | ○ (`SFNNwoP1536` ビルド) | やねうら王に投入するならこれ |
| `SFNN_HALFKA1HM` | `HalfKA_hm1` (後手玉 collapse なし) | 76,950 | × | アブレーション研究用 (両玉を別 plane で持ったときの強さ比較など) |
| `SFNN_KA2` | `K + A2` (玉×駒のクロス積なし) | 1,791 | ○ (`SFNNwoPSQT_ka2_*` ビルド) | 軽量アブレーション ([ka2.md](ka2.md) 参照)。入力層に玉×駒の相互作用が無いため HalfKA_hm2 より loss plateau が高い |

## アーキテクチャ

`--arch SFNN_halfkahm2_1536_15_32_k3k3` を指定したときの内部構造 (やねうら王 `architectures/sfnnwop-1536.h` 準拠):

```
入力特徴量 (HalfKA_hm2: 73,305 次元 × 自他 2 perspective)
        │
        │  L0 affine (Feature Transformer)
        ▼
   FT 出力 (1,536 次元 × 2 perspective)
        │
        │  CReLU + pairwise-mul × (127/128) → concat → 1,536 次元
        ▼
   ─── For each of 9 buckets (LayerStacks; --arch の k3k3 suffix で選択) ───
        │
        │  L1 affine: 1,536 → 16  (= 15 hidden + 1 PSQT shortcut neuron)
        ▼
   ─ 分岐 ─
   ├─ l1_main (15 dim)
   │      │
   │      │  l1_sqr = l1_main² × (127/128)          // SqrClippedReLU 相当
   │      │  L2_input = concat(l1_sqr, l1_main)     // 30 dim, [SqrCReLU; CReLU]
   │      │  CReLU
   │      ▼
   │  L2 affine: 30 → 32 ── CReLU ── L3 affine: 32 → 1
   │                                       │
   │                                       ▼
   └─ l1_skip (1 dim, PSQT shortcut) ───── + ──→ 最終スカラー
```

`--arch SFNN_halfkahm2_1536_15_32_k3k3` は `(ft_size, l1_hidden, l2_size) = (1536, 15, 32)` にマップされる。`l1_hidden + 1` の PSQT shortcut neuron 加算は自動。

組み込み alias は **`SFNN1536`** で、明示的な同等 architecture は **`SFNN_halfkahm2_1536_15_32_k3k3`**。

## LayerStacks=9 (バケット選択)

各局面で複数のサブネットのうち **1 個** だけが使われる。どれを使うかは `--arch` の LayerStack suffix で決まる。古典的な SFNN-1536 構成の `k3k3(king3-by-king3)` では:

| 区分 | 自玉段 (`f_rank`) | 敵玉段 (`e_rank`) |
|---|---|---|
| 上 (0) | 1〜3 段 | 1〜3 段 |
| 中 (1) | 4〜6 段 | 4〜6 段 |
| 下 (2) | 7〜9 段 | 7〜9 段 |

→ バケット = `f_part × 3 + e_part` (0〜8、9 通り)。やねうら王 C++ の `evaluate_nnue.cpp::stack_index_for_nnue` と完全一致する選択ロジック。

詳しくは [応用編: LayerStack](../advanced/layerstack.md) を参照。

## `nn.bin` バイナリレイアウト

やねうら王ソース (`source/eval/nnue/evaluate_nnue.cpp` 等) との byte 単位互換。実装は `crates/bulletou_lib/src/value/nnue_save_sfnn1536.rs` に集約。

```text
[Header]
  u32 LE: NNUE_VERSION = 0x7AF32F16     ← やねうら王 kVersion、不一致だと load 失敗
  u32 LE: kHashValue   = 0x3C203B32     ← SFNNwoPSQT 固定値、warning だけで load 続行
  u32 LE: arch_desc_len
  bytes : "ModelType=SFNNWithoutPsqt;Features=HalfKA_hm2(Friend)[73305->1536x2],Network=SFNN-1536{LayerStack=9}"

[FeatureTransformer]
  u32 LE: FT hash = 0x5F134AB8         ← SFNN 固定値、warning のみ
  [LEB128 block: biases]
    17 bytes: "COMPRESSED_LEB128"      ← LEB128 圧縮マジック
    u32 LE  : payload size
    bytes   : signed-LEB128 encoded i16 × 1536
  [LEB128 block: weights]
    17 bytes: "COMPRESSED_LEB128"
    u32 LE  : payload size
    bytes   : signed-LEB128 encoded i16 × (1536 × 73305)

[× 9 LayerStacks]
  u32 LE: Network hash = 0x6333718A   ← SFNN 固定値、warning のみ
  fc_0 biases  : i32 LE × 16          ← scale = QA × QB = 8128
  fc_0 weights : i8 × 16 × pad32(1536) = 24,576 bytes   ← scale = QB = 64, row-major (out, in)
  fc_1 biases  : i32 LE × 32          ← scale = 8128
  fc_1 weights : i8 × 32 × pad32(30)  = 1,024 bytes     ← scale = 64, in 軸は 30→32 にゼロ padding
  fc_2 biases  : i32 LE × 1           ← scale = 8128
  fc_2 weights : i8 × 1 × pad32(32)   = 32 bytes        ← scale = 64
```

ハッシュ値はやねうら王側で **warning に降格** されている (`evaluate_nnue.cpp:178-179` / `:203-209`、コメント「値の変更を忘れてプルリクしてきた開発者がいる」)。NNUE_VERSION のみ load 必須。

### 量子化スケール

| 部位 | 型 | スケール | 由来 |
|---|---|---|---|
| FT biases / weights | i16 | QA = **127** | Stockfish 標準 (ClippedReLU 後の値域上限 ±127) |
| fc_0 / fc_1 / fc_2 biases | i32 | QA × QB = **8128** | 同上 |
| fc_0 / fc_1 / fc_2 weights | i8 | QB = **64** | やねうら王 `kWeightScaleBits = 6` (= log2(64)) と整合 |

bullet-shogi 上流と同じ値。

### SIMD permutation

やねうら王の `AffineTransform*Explicit::get_weight_index_scrambled` は **read 時** に file byte を chunk-major のメモリ位置にマップする。書き手 (BulletOu) は **row-major (out outer, in inner)** で素直に並べれば OK、scramble はエンジン読み込み時に内部で適用される。padding 領域 (in >= in_dim_real) は `0` 埋め。

詳細は `crates/bulletou_lib/src/value/nnue_save_sfnn1536.rs` の doc-comment 参照。

## やねうら王での load 確認

学習後、最新 save dir を `EvalDir` に指定:

```
setoption name EvalDir value C:/shogi/BulletOu/checkpoints/SFNN_HALFKA2HM-SFNN_halfkahm2_1536_15_32_k3k3/0005
isready
bench
```

`isready` 段階で次の warning が出る (これは想定動作):

```
info string Warning: NNUE hash mismatch: expected 1009484594 got 1009484594 ...
```

(やねうら王はハッシュ不一致を warning に降格して load 続行する。)

`bench` でスコアが出力されれば構造的に正しい。

## ハイパーパラメータの指針

- 教師は数億〜数十億局面規模で、事前 shuffle または `--teacher-shuffle-buffer-sbs` による学習時 shuffle を使う ([チュートリアル: 教師データを用意する](../tutorial/2-data.md))
- `--lambda` は 0.5 〜 1.0 の範囲が一般的 (NNUEwoPSQT は eval スコア重視の設計)
- `--max-epochs` は 1〜3、`--save-rate 10` 程度で後半 save を選ぶ運用。epoch 末尾 save はデフォルトで有効

学習スケジュールの基本は [応用編: 学習設定を調整する](../advanced/tuning.md) を参照。

## メモリ要件

LayerStacks=9 × `(L1 + L1f + L2 + L3)` の重みを GPU 上に持つため、HalfKP の単一 NN より重い。**8 GB+ の GPU 推奨**。FT (1536 × 73305 × i16 = 約 225 MB) は CPU 側 RAM にも展開される。
