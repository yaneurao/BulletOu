# 1. NNUE の基礎

[English](../en/1-basics.md) / **日本語**

## 単純なフィードフォワードネットワーク

### 入力

チェス用の基本的なニューラルネットの入力は `768 = 2 × 6 × 64` 個の 0/1 を並べたベクトル。あるインデックスが 1 なら、特定の駒が特定のマスに存在することを表し、0 なら不在を表す。

標準的なやり方は、`white_pawn = 0, white_knight = 1, ..., black_pawn = 6, ..., black_king = 11` と駒種を番号付けし、マス `Square` に駒 `Piece` がある場合、入力ベクトルの `64 × Piece + Square` 番目の要素を 1 にする、というもの。

以後、この入力ベクトルを $\mathbf{x}$ と書く。

### 隠れ層

`768 -> N -> 1` ネットワークの隠れ層は `N` 次元ベクトルで、入力ベクトルの関数として定義される。そのために以下を導入する:

- $H$ — 隠れ層の重み。`N × 768` 行列
- $\mathbf{b}$ — 隠れ層のバイアス。N 次元ベクトル
- $\rho$ — 活性化関数。任意のベクトルに対し要素ごとに作用する

これらを使って、アキュムレータを $\mathbf{a} = H \mathbf{x} + \mathbf{b}$ と定義し、隠れ層は $\mathbf{h} = \rho(\mathbf{a})$ となる。

### 出力層

出力 $y$ はスカラー値 (チェスエンジンで使うため)。以下を定義する:

- $O$ — 出力の重み。`1 × N` 行列
- $c$ — 出力のバイアス。スカラー定数

出力は $y = O \mathbf{h} + c$ で定義される。`1 × N` 行列と N 次元ベクトルの積は `1 × 1` 行列 (= スカラー) になる点に注意 ($O$ をベクトルとして定義して内積を使っても等価だが、ここでは表記の一貫性のために行列で書く)。

### まとめると

計算全体を書き下すと:

$$
y(\mathbf{x}) = O \rho( H \mathbf{x} + \mathbf{b} ) + c
$$

## Perspective ネットワーク (両視点ネットワーク)

`768 -> N×2 -> 1` の perspective ネットワーク構造は上と非常に似ているが、入力が 2 種類ある: $\mathbf{x}$ と $\mathbf{\hat{x}}$。

前述のネットワークと異なり、$\mathbf{x}$ は白視点ではなく、駒種を **手番側 (STM = side to move) から見て** `friendly_pawn = 0, ..., enemy_king = 11` と番号付けする。$\mathbf{\hat{x}}$ は同じだが **反対側の視点** から見たもの。

アキュムレータが 2 つになる: $\mathbf{a} = H \mathbf{x} + \mathbf{b}$ と $\mathbf{\hat{a}} = H \mathbf{\hat{x}} + \mathbf{b}$。出力は以下になる:

$$
y = O \rho(\mathrm{concat}(\mathbf{a}, \mathbf{\hat{a}})) + c
$$

この場合、$O$ を $O_1$ と $O_2$ に分割すると、等価に以下のように書ける:

$$
y = O_1 \rho(\mathbf{a}) + O_2 \rho(\mathbf{\hat{a}}) + c
$$

推論時には通常この形式を使う。

## 初心者がはまりやすい罠

### あまり良くない入門資料

#### 著者の強い NNUE エンジンに裏打ちされていない、ほとんどの NNUE 解説記事/ブログ/本

- NNUE の核となる概念はそれなりにうまく説明されていることもある
- それ以外の細部は、根拠の乏しい・的外れなアドバイスであることが多い

#### Stockfish のネットワーク構造

- ここで言っているのは **アーキテクチャ** であって、実際の SF ネットワーク (これらは明らかに非常に優秀) のことではない
- SF のアーキテクチャは多くのエンジンに模倣されてきた
- SF アーキテクチャの多くの側面は、実際に Elo を得るために **多大な** 労力・データ・学習時間・複雑さを要する
- 結果として、特に初心者が SF アーキテクチャを採用すると、もっと単純なものと比べて *Elo を失う* ことが (おそらく) 起きる

#### [nnue-pytorch の nnue.md](https://github.com/official-stockfish/nnue-pytorch/blob/master/docs/nnue.md)

- 一般的な SF NNUE の歴史 + 一部の発展的内容については良い資料
- 上に書いたことの続き:
  - これは Stockfish NNUE についてのドキュメント
  - あなたが書いているのは Stockfish ではない
- 初心者が必要とする情報量を大きく超えていて、全体として混乱しやすい
- まともなスタート地点として最も妥当なアーキテクチャを [おもちゃの例](https://github.com/official-stockfish/nnue-pytorch/blob/master/docs/nnue.md#a-simple-input-feature-set) として扱っている
- 内容の大部分について、おおむね時代遅れになっている

### 段階を飛ばすこと

一般論として、シンプルなところから始めて、各段階で実際に Elo が向上することを確認しながら段階的に複雑さを上げていくのが良い実践。

下記の罠との関連:本ドキュメント執筆時点で、Alexandria 7.0.0 は CCRL Blitz 1CPU で 6 位にあり、そのネットワーク構造は `(768->1536)×2 -> 1×8`、つまり入力 bucket は **なし**、隠れ層もたった 1 層。

#### 巨大な入力特徴量

- まずは基本の 768 入力から始めること
- HalfKA/HalfKP のようなものは、最初は (おそらく永久に) 十分な学習データが得られない。データが少ない局面では独自 bucket スキームの方が一般に良い結果になる

#### 隠れ層を 2 層以上にすること

- 通常は、最初の隠れ層のサイズを増やす方が有益 (少なくとも 1024 まで)
- 層を増やすこと自体は固定ノード数で Elo を上げる効果はあるが、推論速度の低下による Elo 損失を回避する実装は非自明
- 手書き SIMD と、よく考えられた量子化技術が必要
