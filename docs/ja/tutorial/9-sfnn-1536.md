# 9. SFNN-1536 (NNUEwoSQPT1536) を学習する

<a href="../../en/tutorial/9-sfnn-1536.md"><img alt="Read in English" src="https://img.shields.io/badge/Lang-English-DC2626?style=flat-square"></a>

やねうら王の `YANEURAOU_ENGINE_NNUE_SFNNwoP1536` ビルド (= 通称 NNUEwoSQPT1536) で動く評価関数を学習する。SFNN-1536 は **LayerStacks ファミリ** に属し、ふつうの NNUE と次の点が違う:

- **9 個の独立した MLP (LayerStacks=9)** を持ち、局面ごとに「両玉の段の組み合わせ (3×3)」で 1 個を選んで使う
- 入力特徴量は **HalfKA_hm2** (= `HalfKA + half-mirror + 後手玉を自玉 plane に collapse`)
- 中間で **SqrClippedReLU と ClippedReLU のペア出力** を concat (`AffineTransformSparseInputExplicit` + `ClippedReLUExplicit` + `SqrClippedReLU` の組合せ)
- **PSQT shortcut**: fc_0 出力の余分な 1 neuron を fc_2 出力に直接バイパス加算

## 9.1 コマンド

最小:

```bash
./target/release/examples/bulletou \
    --eval-type SFNN_HALFKA2HM \
    --arch 1536x2-15-32 \
    --layerstack king3-by-king3 \
    --teacher teachers/
```

これがやねうら王同梱の `architectures/sfnnwop-1536.h` と byte-for-byte 互換となるべき構成。`--output` 省略時は `checkpoints/SFNN_HALFKA2HM-1536x2-15-32-king3-by-king3/` 配下に書く。

## 9.2 v1 / v2 の使い分け

`--eval-type` の 2 候補:

| flag | 入力特徴量 | 入力次元 | やねうら王 load 可 | 用途 |
|---|---|---|---|---|
| **`SFNN_HALFKA2HM`** ★ 通常はこちら | `HalfKA_hm2` (後手玉 collapse あり) | 73,305 | ○ (`SFNNwoP1536` ビルド) | やねうら王に投入するならこれ |
| `SFNN_HALFKA1HM` | `HalfKA_hm1` (後手玉 collapse なし) | 76,950 | × | アブレーション研究用 (両玉を別 plane で持ったときの強さ比較など) |

両者の違いは **入力特徴量モジュールだけ**。NN 構造・量子化・LayerStacks の仕組みはすべて同じ。

## 9.3 `--layerstack` の選択

`--layerstack` フラグで「9 個のサブネットをどう使い分けるか」を選ぶ。現状サポートされている値は 1 つだけ:

| flag | バケット選択ロジック | やねうら王 load 可 | 備考 |
|---|---|---|---|
| **`king3-by-king3`** (デフォルト) | 自玉段 3 区分 × 敵玉段 3 区分 = 9 | ○ | やねうら王の `stack_index_for_nnue` と完全一致 |

将来やねうら王側で別のバケット選択スキーム (例えば手数バケット版 SFNN) が追加されたらここに足します。`Ply9` / `Progress8*` 等の研究用バケットモードのコード自体は `bulletou_lib::game::outputs::ShogiLayerStackBucket9` に残してあり、`examples/shogi_layerstack.rs` (rshogi 経路) では引き続き利用可能。

## 9.4 NN アーキテクチャの中身

`--arch 1536x2-15-32` を指定したときの内部構造 (やねうら王 `sfnnwop-1536.h` 準拠):

```
Feature Transformer (l0):  73305 → 1536  (per perspective)
[CReLU + pairwise-mul + (127/128)] × 2 perspectives → concat → 1536

For each of 9 buckets (selected by --layerstack):
  L1:   1536 → 16  (= 15 hidden + 1 PSQT shortcut neuron)
  ─ split: l1_main (15 dim) / l1_skip (1 dim, PSQT shortcut)
  l1_sqr = l1_main² × (127/128)
  L1_input_to_L2 = concat(l1_sqr, l1_main)            // 30 dim, [SqrCReLU; CReLU]
  CReLU → L2:  30 → 32
  CReLU → L3:  32 → 1

Final scalar = L3_out + l1_skip                        // PSQT bypass
```

`--arch` は内部的に `(ft_size, l1_hidden, l2_size) = (1536, 15, 32)` にマップされる。`l1_hidden + 1` の PSQT shortcut neuron 加算は自動。

## 9.5 重要な制約

### YaneuraOu 互換 `nn.bin` の保存

各 save dir に **やねうら王 `YANEURAOU_ENGINE_NNUE_SFNNwoP1536` ビルド向けの `nn.bin`** が書かれる。`bulletou_lib::value::nnue_save_sfnn1536` がやねうら王ソース (`evaluate_nnue.cpp` / `nnue_feature_transformer.h` / `sfnnwop-1536.h` / `affine_transform_*.h`) と整合する layout を出力する:

- ヘッダ: `NNUE_VERSION = 0x7AF32F16` (やねうら王 `kVersion` 必須)、wide hash `0x3C203B32`、arch description `"ModelType=SFNNWithoutPsqt;..."` 形式
- FT: hash `0x5F134AB8` (固定) + biases/weights を **LEB128 圧縮 2 ブロック** (`COMPRESSED_LEB128` magic + payload、SFNN 必須経路)
- 各 LayerStack (×9): hash `0x6333718A` (固定) + fc_0 (i32 bias × 16 + i8 weight × 16×1536) + fc_1 (i32 bias × 32 + i8 weight × 32×32) + fc_2 (i32 bias × 1 + i8 weight × 1×32)
- 量子化スケール: QA=127 (FT)、QB=64 (各 fc weight)、QA×QB=8128 (各 fc bias)、いずれも Stockfish/bullet-shogi の標準値
- 検証: やねうら王エンジン `setoption name EvalDir value <output>/000N → isready → bench` で load 確認する。**`info string Warning: NNUE hash mismatch` は出るが load 続行**する (やねうら王はハッシュ不一致を warning に降格しているため、`evaluate_nnue.cpp:178-179` / `evaluate_nnue.cpp:203-209` を参照)

サポート状況:
- ✓ `--eval-type SFNN_HALFKA2HM` で学習が走り、`state.bin` (resume 用) + やねうら王互換 `nn.bin` が毎 save に出力される
- ✓ `learn.log` で loss 推移確認可
- ✓ resume も他 eval-type と同じく自動

### `--arch` は事実上 `1536x2-15-32` 一択

やねうら王同梱の SFNN ビルドは 1536x2-15-32 のみ。他のサイズ (`256x2-32-32` 等) を指定しても学習は通るが、生成した nn.bin は **やねうら王に load できない** (Phase 4 が完成しても)。アブレーション専用。

### LayerStacks=9 は固定

`--layerstack king3-by-king3` の **stack 数は 9** (やねうら王 nn.bin が 9 stacks を期待するため)。stack 数が異なる bucketing (例: `progress8`) は CLI から到達できない (研究用には `examples/shogi_layerstack.rs` 経由)。
